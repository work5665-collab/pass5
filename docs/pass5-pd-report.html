핵심 결론

가장 큰 장벽은 UI 조작이 아니라 콘텐츠 불일치다. PASS 5 프레임워크의 15개 카드·26개 필드는 전부 “Vercel 배포 · MVP · 오픈소스 · 깃허브 커밋 · KPI 시간단축” 같은 소프트웨어·기술 프로젝트 전용으로 하드코딩되어 있다. 홍보영상 PD는 거의 모든 질문에서 무관한 선택지를 버리고 “직접 입력”을 강제당한다. 그리고 이 앱에는 AI 추천·가이드 기능이 전혀 없다. 드롭다운 선택지 + 주관식 입력 + “기존 옵션 가져오기”뿐이다. 초반 공수를 줄이려는 사용자 요구와 정면으로 배치된다.

SCENARIO페르소나 여정 워크스루

PD가 “테스트 홍보 영상 A 제작” 프로젝트를 만들고 Input 단계를 채우고 뷰를 오가는 실제 경로를, 렌더링되는 코드를 따라 재구성했다.

STEP 1

프로젝트 진입 — “테스트 홍보 영상 A 제작”

의도

막연한 한 줄 의뢰를 들고 프로젝트를 시작한다.

실제 동작

사이드바 “새 프로젝트” → 이름만 입력 → 자동 선택 + 칸반 진입. 진입 자체는 매우 빠르고 쉽다. 그러나 프로젝트 생성 시 업종·도메인(영상 제작)을 묻는 단계가 없어, 템플릿은 그대로 소프트웨어 전용으로 로드된다. 이 시점부터 PD는 “이 질문들이 내 홍보영상과 무슨 상관이지?”라는 막막함을 안고 시작한다.

문제: 진입 장벽은 낮지만, 잘못된 프레임워크가 이미 선택되어 있어 이후 모든 입력이 어긋난다. 도메인 설정의 기회를 놓치는 지점.

STEP 2

Input — “목적과 문제 정의” 카드 작성 핵심 난관

의도

초반 입력 공수를 최소화하고, 막막할 때 가이드를 받고 싶다.

실제 동작

칸반 카드 클릭 → 상세 뷰. 각 필드는 드롭다운 셀렉트 + 마지막 옵션에 숨겨진 “✏️ 직접 입력(주관식 작성)”. 제공 선택지 예: 파편화된 업무 프로세스의 일원화 수동 반복 업무 자동화 오픈소스 기반 워크플로우 정착 — 홍보영상과 무관한 것뿐. PD는 전 필드에서 무관한 보기를 고르거나, 숨은 “직접 입력”을 찾아 일일이 타이핑해야 한다.

부담

15개 카드 · 26개 필드가 전부 같은 패턴. 선택지가 안 맞으니 모든 필드를 수동 오버라이드하는 공수가 발생. 사용자가 줄이려 했던 “초반 카드 입력 공수”가 최대치가 되는 구간.

문제: (1) 프레임워크·선택지가 영상 제작에 미스매치. (2) “직접 입력”이 드롭다운 끝에 숨어 발견 어려움. (3) AI 추천·선택지 재생성 기능 없음. 막막함이 가장 크게 터지는 곳.

STEP 3

동선 — 칸반 · 집중 · 종합정의서 간 이동 양호

의도

전체 맥락과 세부 작성 사이를 매끄럽게 오가고 싶다.

실제 동작

칸반 카드 클릭→상세. 상세엔 뒤로가기 ⬆ 해당 단계 집중뷰 전체 칸반(인덱스). 집중뷰엔 뒤로가기 + 인덱스 + “세부 수정”. 종합정의서엔 sticky 5단계 네비게이터, 그리고 미작성 필드 (미작성) 클릭 → 해당 카드 상세로 이동. 뒤로가기는 historyStack으로 직전 뷰에 정확히 복귀(정의서에서 미작성 클릭 → 상세 → 뒤로 → 정의서 복귀). 우하단 TOP 버튼은 300px 스크롤 시 표시, 클릭 시 부드럽게 최상단.

경미한 마찰: 한 화면에 이동 버튼이 3~4개(뒤로 / 인덱스 / 집중뷰 / 상세)라 초기엔 “어느 버튼이 어디로 가는지” 혼란. 집중뷰에선 미작성 필드가 클릭 불가(종합정의서에만 있음). 5단계 네비게이터의 scrollIntoView는 메인 스크롤 컨테이너와의 상호작용 엣지가 있을 수 있음.

PRIORITYAI 가이드가 가장 시급한 위치

“제작자의 기획 공수를 줄이기 위한 AI 질문 추천/선택지”가 실제로 닿아야 할 핵심 지점을 영향력 순으로 정렬했다.

01

Input 단계 필드 작성 화면 (상세 뷰의 선택 영역) — 최우선

각 드롭다운/직접입력 옆에 “✨ AI 추천 답변” · “이 프로젝트에 맞는 선택지 재생성” 버튼. 프로젝트 이름(“테스트 홍보 영상 A”)을 읽고 영상 제작용 답변·선택지를 즉석 제안. 막막함이 가장 크게 터지는 바로 그 지점에 삽입되므로, 초반 기획 공수를 가장 직접적으로 줄인다.

왜 최우선: 사용자가 “막막할 때 가이드”를 원하는 순간이 정확히 여기이며, 전체 26개 필드에 일괄 적용되는 승수 효과가 있다.
02

프로젝트 생성 직후 — 도메인 원샷 설정 (근본 해결)

생성 시 “이 프로젝트는 무슨 유형인가요?”(영상 제작 / 소프트웨어 / 마케팅…)를 묻고, 전체 프레임워크 카드·선택지를 그 도메인에 맞게 재스코프. 템플릿 불일치의 뿌리를 끊는 전략적 해법으로, 1순위보다 배치 위치는 앞서지만 구현 비용이 크고 지금의 막막함에 즉시 닿지는 않는다.

왜 중요: 1순위를 아무리 잘 만들어도 프레임워크가 소프트웨어 전용이면 근본 공수는 남는다. 두 기능은 함께 가야 한다.
03

종합 정의서의 (미작성) 필드 — AI 초안 생성

미작성 항목에 “✍️ AI 초안 생성” 제안(기존에 채운 입력을 바탕으로 문장 초안). 정의서가 “완성된 문서”로 보이게 하는 마감 심리를 돕는다.

04

Review / KPT 회고 단계 — 회고 초안

KPT 카드에 입력 데이터 기반 회고 초안 생성. 공수 절감보다는 완성도를 높이는 보조 위치.

METHOD & LIMITS테스트 방법과 제약

평가를 실제로 어떻게 수행했는지 투명하게 기록한다.

항목내용
배포 URLVercel 배포 후보 URL(pass5-taupe.vercel.app 등) 모두 HTTP 404. 배포가 제거/미확인 상태 → 로컬 dev 서버(:3000, 200 OK)로 대체.
수행 방식Google OAuth 로그인이 필요해 실제 브라우저 자동화 로그인은 불가. 대신 렌더링되는 소스 코드 정밀 워크스루로 모든 뷰(칸반·집중·상세·종합정의서)와 내비게이션 핸들러, 필드 입력 로직, 프레임워크 콘텐츠(lib/framework.ts)를 추적해 에이전트 탐색 경로를 시뮬레이션.
주요 근거app/page.tsx(뷰·동선) · components/KanbanBoard.tsx(칸반·카드 진입) · lib/framework.ts(15카드·26필드 선택지) · ProjectSidebar.tsx(프로젝트 생성).
한계실제 마우스 호버·드래그·스크롤 물리감, 웹 접근성 실측은 미포함. 점수는 코드 기반 정성 평가.
